# 开发计划、测试与上线门槛

## 1. 分期建议

### Phase 0｜需求冻结（3–5 个工作日）

- 确认平台、交易商、品种映射、策略边界、风险参数和角色权限。
- 固化 OpenAPI、TradePlan JSON Schema、原因码和审计字段。
- 对原型完成页面评审，形成真实数据字段清单。

交付：需求基线、威胁模型、接口契约、测试用例目录。

### Phase 1｜影子模式 MVP（2–3 周）

- MT5 EA 采集、心跳、快照、订单/持仓同步；不允许真实下单。
- FastAPI、PostgreSQL、Redis、确定性规则和一个模型适配器。
- 五页 Web 面板接真实 API；决策与实际行情并排记录。
- 完成签名、幂等、超时、重试、数据新鲜度与基本监控。

交付：OBSERVE 模式端到端闭环。

### Phase 2｜模拟盘执行（2–3 周）

- 本地硬风控、仓位计算、开仓/改单/部分平仓/关仓。
- CONFIRM 与 AUTO 模式、控制指令、熔断、断线恢复和对账。
- 策略测试器、录制回放、故障注入和性能测试；因 MQL5 Strategy Tester 不支持 WebRequest，使用分析接口适配层 + 本地固定桩/录制数据替代真实 HTTP。

交付：模拟盘可执行版本与测试报告。

### Phase 3｜实盘灰度（至少 2 周）

- 独立实盘环境、MFA、密钥轮换、备份恢复、值班告警。
- 单账户小资金、低风险上限；逐日评审计划与成交偏差。
- 达到门槛后逐步扩大，不达标自动回到 OBSERVE。

## 2. 测试矩阵

| 类别 | 必测场景 |
|---|---|
| 契约 | Schema 版本、未知字段、缺失字段、非法枚举、精度/时区 |
| 安全 | 签名错、nonce 重放、时钟偏差、越权、密钥轮换、日志脱敏 |
| 幂等 | 请求重试、回执重传、终端重启、网络抖动、服务端重复消费 |
| 风控 | 点差、滑点、保证金、日亏、回撤、连续亏损、仓位/方向限额 |
| 交易 | 市价/挂单、部分成交、拒单、重报价、最小距离、品种后缀 |
| 降级 | API/模型/Redis/数据库/新闻源故障、慢响应、返回脏数据 |
| 对账 | EA/后端持仓差异、孤儿订单、人工在终端交易、历史补传 |
| 前端 | 空态、过期、断线重连、序列跳号、权限、危险操作双确认 |
| 策略 | 前视偏差、过拟合、手续费/点差/滑点、跨市场阶段稳定性 |

## 3. 模拟盘上线门槛

- 所有 P0/P1 测试通过；无未解释的重复单、漏单和孤儿持仓。
- 断网/重启后 5 分钟内完成对账，且不会重复执行旧计划。
- 任何 API/模型异常都不能绕过本地硬风控。
- 面板与交易终端关键状态一致，数据过期能在 2 秒内显著提示。
- 紧急停止和恢复流程完成桌面演练，有明确操作者与审计记录。

## 4. 实盘灰度门槛

- 模拟盘连续至少 2 周稳定；策略样本量与评估周期由业务另行定门槛。
- 计算已计入真实点差、佣金、隔夜费、滑点和网络延迟。
- 已完成备份恢复、密钥泄露、模型不可用、行情异常的演练。
- 风险负责人书面确认限额；AUTO 默认关闭，通过审批后逐账户开启。

## 5. 主要风险

- 参考图展示的是产品概念，不能证明策略盈利能力。
- AI 输出可能漂移、延迟或格式异常，必须由 Schema、规则和本地风控围住。
- 回测/演示收益不能替代样本外、模拟盘和小资金实盘验证。
- 不同交易商的点值、最小手数、止损距离、交易时段和品种后缀必须实测。
- 新闻与经济日历常受授权和延迟限制，需确认数据许可与故障降级策略。
