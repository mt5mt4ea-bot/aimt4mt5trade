# AI 开单 EA 开发需求设计

版本：0.1（前期方案）  
范围：XAUUSD 单品种 MVP，可扩展到外汇/指数；图片内容仅用于提取视觉和产品需求。

## 1. 产品目标

系统在 MetaTrader 中采集行情、账户和持仓信息，调用服务端分析 API 生成带证据与置信度的交易计划，经 EA 本地硬风控后自动开仓、管理持仓和关仓，并在 Web 面板实时展示决策依据、行情状态、执行轨迹、复盘结果和风险状态。

首版不追求“模型自主控制账户”，而是构建一条可审计、可暂停、可回滚的自动交易链路。

## 2. 用户角色

| 角色 | 权限 |
|---|---|
| 观察者 | 查看行情、决策、交易和风险，不可改参数 |
| 交易员 | 启停自动交易、手动确认/拒绝计划、平仓、撤单 |
| 风控管理员 | 修改限额、触发全局熔断、解锁需二次确认 |
| 系统管理员 | 账户绑定、密钥轮换、模型/策略版本发布和审计 |

## 3. 系统边界

- EA 负责：行情/指标快照、账户与订单同步、签名调用、计划校验、本地风控、下单与改单、成交回报、断线保护。
- API 负责：数据标准化、特征计算、规则与 AI 协同决策、计划签名、持仓管理建议、事件落库、推送面板。
- Web 面板负责：观察、解释、配置、人工干预、复盘与审计；浏览器不能直接连接交易商或绕过 EA 发单。
- 外部数据负责：经济日历、新闻、波动率/情绪等辅助证据。外部源失败时必须降级，不得伪造数据。

## 4. 核心流程

### 4.1 分析与开仓

1. EA 在新 K 线、固定周期或人工请求时生成 `MarketSnapshot`，包含 OHLCV、点差、ATR、指标、多周期结构、账户与持仓摘要。
2. EA 使用 HMAC 签名调用 `POST /v1/analysis/requests`，同时传递 `request_id`、服务器时间和策略版本。
3. 分析服务执行数据新鲜度检查、技术/多周期/宏观/资金面/形态/入场时机/波动性因子评分。
4. 决策引擎输出 `LONG | SHORT | FLAT | HOLD | CLOSE | REDUCE`，置信度、证据、反证、入场区间、止损、止盈、失效时间和风险预算。
5. 风控服务先做服务端预检，签发不可篡改的 `TradePlan`；置信度未达开仓线时只显示，不发开仓动作。
6. EA 校验签名、时钟偏差、计划有效期、品种映射、报价偏移、重复请求和本地硬风控。
7. 自动模式下执行；半自动模式在面板确认后执行；观察模式永不执行。
8. EA 回传 `accepted/rejected/submitted/filled/partial/failed` 事件，前端实时更新。

### 4.2 持仓管理与关仓

- 每个持仓由 EA 本地 SL 兜底；服务端可以建议移动止损、分批止盈、减仓或平仓。
- 以下事件触发重新分析：新 K 线、价格越过管理阈值、浮亏/浮盈阈值、重大新闻窗口、点差异常、持仓超时、人工请求。
- `CLOSE/REDUCE/MODIFY_SL/TAKE_PARTIAL` 同样使用计划签名、有效期和幂等键。
- 全局熔断、账户硬止损与紧急平仓不依赖 AI；API 不可用时仍由 EA 执行本地保护。

## 5. EA 功能需求

### 5.1 输入参数

| 分组 | 参数示例 | 默认建议 |
|---|---|---|
| 连接 | API Base URL、账户标识、Key ID、请求超时 | 超时 8 秒，最多 2 次退避重试 |
| 运行 | `OBSERVE/CONFIRM/AUTO`、分析周期、Magic | 默认 OBSERVE |
| 品种 | 交易品种、后缀映射、允许方向 | XAUUSD、双向 |
| 仓位 | 固定手数/风险百分比、最大单笔风险 | 风险百分比，0.5% |
| 限额 | 最大总手数、最大持仓数、日亏损、回撤 | 1 单；日亏 2%；最大回撤 10% |
| 交易质量 | 最大点差、最大滑点、最小止损距离 | 按交易商规格动态校验 |
| 时间 | 允许时段、周五收盘、新闻前后禁开 | 新闻前后 15/15 分钟 |
| 管理 | 保本、移动止损、分批止盈、最大持仓时长 | 可配置，服务端建议不可放宽硬限制 |

### 5.2 本地硬风控（优先级最高）

- 账户号与授权账户必须一致；实盘/模拟环境不可混用密钥。
- 仅处理本 EA 的 Magic + order comment；紧急账户熔断可按配置处理全账户。
- 保证金水平不足、交易关闭、点差超限、报价过旧、滑点超限、市场冻结时拒绝。
- 单笔风险、同向暴露、总手数、持仓数、当日亏损、连续亏损和最大回撤任一超限即拒绝。
- 已有同一 `plan_id` 或 `idempotency_key` 的成功/处理中记录时禁止重复发单。
- API 断线时不新开仓；已有仓位继续执行本地 SL/TP、保本和熔断逻辑。
- 服务端指令只能收紧风险，不能越过 EA 编译时/本地配置的上限。

### 5.3 EA 状态机

`BOOT → AUTHENTICATING → SYNCING → READY → ANALYZING → PLAN_RECEIVED → RISK_CHECK → SUBMITTING → MANAGING`

异常分支：

- 任意状态可进入 `DEGRADED`（API/数据源异常）：禁止新开仓，保留本地持仓保护。
- 风险阈值触发进入 `HALTED`：禁止新开仓，是否平仓由熔断级别决定。
- 仅管理员双确认、风险恢复且完成账户同步后，`HALTED → SYNCING → READY`。

### 5.4 Tick 与 Timer 分工

- `OnTick`：轻量报价更新、SL/TP/熔断检查，严禁在每个 Tick 同步等待 AI。
- `OnTimer`：心跳、订单增量同步、计划轮询、失败事件重传。
- 新 K 线检测：打包快照并异步化调用；MQL WebRequest 虽为同步，应采用短超时和任务状态查询，避免卡住交易线程。
- `OnTradeTransaction`（MT5）：捕获委托、成交、持仓变化；事件到达顺序不保证且队列有限，处理函数只做轻量入队/记录，MT4 通过定时快照差异补偿。
- MQL5 `WebRequest` 不能在 Strategy Tester 中运行；回测时必须通过 `IAnalysisProvider` 适配层读取本地录制计划/固定桩数据，不能把真实 HTTP 作为测试前提。

## 6. 决策模型要求

每次输出必须符合严格 JSON Schema，不允许自由文本作为交易指令。建议字段：

- `action`、`symbol`、`side`、`order_type`、`entry_zone`
- `stop_loss`、`take_profit[]`、`risk_percent`、`max_slippage_points`
- `confidence`、`open_threshold`、`expires_at`
- `factors[]`：类别、方向、分数、权重、证据时间
- `supporting_evidence[]`、`counter_evidence[]`、`reason_summary`
- `model_version`、`strategy_version`、`prompt_version`、`data_timestamp`

建议采用“确定性规则 + 模型解释/综合”的混合方式。技术指标、仓位大小和风险限额由代码计算；模型负责跨因子归纳，不允许模型自行进行关键数值运算。

## 7. 非功能需求

- 可用性：交易时段 API 月可用性目标 99.9%；降级不影响本地保护。
- 延迟：行情快照到计划 P95 ≤ 8 秒；前端事件更新 P95 ≤ 2 秒。
- 可审计：每个计划可追溯到输入快照、代码/模型/提示词版本、风控结果和成交事件。
- 时钟：所有接口使用 UTC ISO-8601；展示层可切换北京时间/交易商时间。
- 数据保留：原始决策与交易审计不少于 2 年；高频行情按成本分层归档。
- 安全：全链路 TLS、HMAC/短时 JWT、密钥轮换、最小权限、敏感字段脱敏和管理操作二次确认。

## 8. 验收标准

1. 同一计划重复发送 10 次，只产生最多一笔订单。
2. API 超时、返回非法 JSON、签名错误、计划过期时，EA 均拒绝开仓且留下原因码。
3. 任一硬风险阈值触发后，新计划均被拒绝；本地 SL/TP 继续工作。
4. 订单状态在 EA、后端与面板最终一致，断网恢复后能够补传和对账。
5. 面板可从一次成交回溯到完整行情快照、因子、模型/策略版本与执行日志。
6. 回放、模拟盘连续运行 2 周无重复单、孤儿持仓和未解释的状态差异，才允许小资金灰度。

## 9. 开发前需业务确认

- 目标平台是 MT5、MT4，还是双平台；首发交易商及 XAUUSD 的真实符号后缀。
- AI 服务供应商、预算与数据驻留要求；是否允许外部新闻/日历数据。
- 自动模式是否默认关闭；实盘启用所需审批人和最大资金规模。
- 风险阈值、交易时段、新闻禁开窗口、持仓跨夜/跨周规则。
- 固定策略信号与 AI 的职责边界，以及回测基准和可接受最大回撤。
