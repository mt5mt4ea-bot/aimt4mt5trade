# 前端页面与交互设计

## 1. 设计方向

参考图的深色交易终端风格，采用黑灰背景、薄描边卡片、荧光绿色表示正向/多头/健康，珊瑚红表示负向/空头/告警，白色表示中性。界面强调“当前是否安全、系统正在做什么、为什么这样决策”，而不是只展示模型结论。

桌面端采用固定顶部导航 + 12 栏卡片网格；平板降为 6 栏；手机降为单栏。重要操作（启停自动交易、全局熔断、强平）始终显示确认对话框和影响范围。

## 2. 全局结构

- 顶部：品牌、总览/行情/决策/复盘/风控、连接状态、运行模式、账户。
- 状态条：数据时间、市场状态、EA 心跳、API 延迟、策略/模型版本。
- 通用抽屉：决策详情、订单时间线、风险拒绝原因。
- 通用提示：正常、降级、熔断三级；降级和熔断不能只靠颜色表达。

## 3. 总览页 `index.html`

目标：10 秒内回答“现在能否交易、AI 怎么看、账户如何、有没有持仓”。

- 决策场：多/空/中立因子汇聚，显示动作、置信度、开仓阈值和倒计时。
- 账户净值：余额、净值、当日收益和迷你曲线。
- 行情：Bid/Ask、点差、ATR、市场状态。
- 当前信号：方向、置信度、多/空/中立票数、下一动作。
- 执行计划：计划状态、入场区间、SL/TP、风险比例。
- 持仓：方向、手数、均价、浮盈亏；空仓也必须明确显示。
- AI 摘要：理由、反证、风险与数据时间。

交互：点击决策卡进入决策页；点击计划/持仓打开时间线；运行模式切换需要二次确认。

## 4. 行情页 `market.html`

目标：展示做出决策所依赖的行情上下文与数据新鲜度。

- 主图：K 线、成交量/价格分布、关键价位、入场区间、SL/TP 标记。
- 报价卡：Bid/Ask、点差、ATR、波动率状态。
- 动能卡：短期动能、CVD/量价关系、趋势强度。
- 交易时段：亚洲/伦敦/纽约时段和当前重叠情况。
- 经济日历：事件级别、预期/前值、禁开窗口。
- 数据质量：最后更新时间、缺口、源延迟、降级说明。

交互：切换 M5/M15/H1/H4/D1；悬停查看 K 线；点击事件查看禁开规则。原型使用简化 SVG，不代表最终行情图组件。

## 5. 决策页 `decision.html`

目标：解释“结论从哪里来，为什么现在不一定开单”。

- 因子频谱：技术面、多周期、宏观、基本面、资金面、形态、入场时机、波动性。
- 当前决议：动作、置信度、阈值、有效期、策略/模型版本。
- 多空共识：多/空/中立票数与加权分。
- 模块投票：每一模块的方向和置信度。
- 多周期一致性：D1/H4/H1/M15/M5。
- 证据与反证：每条带时间和来源；过期证据置灰。
- 人工操作：确认、拒绝、仅观察；不可编辑模型原始输出，变更应生成新的人工计划。

## 6. 复盘页 `replay.html`

目标：回答“系统最近做得怎样、错误来自哪里、要改什么”。

- 决策轨迹：判断分数、证据分数、开/关仓事件的时间对齐。
- 今日/周期绩效：净利润、成交数、胜率、盈亏比、最大回撤、期望值。
- 最近成交：方向、手数、进出价、盈亏、计划 ID。
- 算法榜单：按策略/模型版本比较样本数、收益、回撤，避免只看胜率。
- 失效分类：信号错、入场差、滑点、风控拒绝、网络/数据异常。
- 复盘建议：仅建议，不可直接修改实盘参数；参数变更需要审批和新版本。

## 7. 风控页 `risk.html`

目标：第一眼看到可用风险额度、运行状态和告警。

- 账户风险：净值/余额、可用保证金、保证金水平、杠杆、日亏、回撤。
- 仓位限额：当前/最大总手数、最大持仓数、单笔风险、品种暴露。
- 运行状态：数据时间、EA 心跳、市场、K 线、自动交易、模型/API 延迟。
- 账号与审计：角色、绑定账户、策略/模型版本、累计决策/开仓次数。
- 市场警报：新闻、点差、波动率和数据源异常。
- 控制区：观察/确认/自动模式、暂停新开仓、紧急平仓、解除熔断。

高风险操作规则：按钮采用“先说明影响 → 输入确认词/二次认证 → 执行 → 返回操作 ID”的流程；执行结果进入不可篡改审计日志。

## 8. 状态和空态

每页至少覆盖以下状态：加载中、无数据、数据过期、API 降级、EA 离线、市场休市、无持仓、权限不足、部分数据源失败。不能用 `0` 冒充缺失值；缺失显示 `—` 并附原因。

## 9. 可访问性

- 正文对比度满足 WCAG AA；红绿之外增加方向文字/图标。
- 键盘可访问导航、按钮、抽屉和对话框；焦点状态清晰。
- 数字使用等宽字体并固定小数位；金额、价格、点数和百分比明确单位。
- 动画遵循 `prefers-reduced-motion`；实时变化不造成布局跳动。
